# Phase 0 결과 기반 논문 방법론 방향 분석 — #1 수집 타겟 / #2 충분성

> **성격**: Phase 0 진단(`results_interpretation.md`) + Phase 1 exposure 설계(`../../phase1/design.md`, `../../phase1/exposure/REVIEW.md`) + 개념틀(`docs/wiki/evaluation/coverage-vs-sufficiency.md`)을 종합해, 논문용 연구결과를 위한 방법론 #1·#2를 어떻게 구현할지 분석한 노트.
>
> **연구 질문 3개**: ① 무엇을 수집하는 게 효과적인가(방향 설정), ② 충분히 확보된 케이스는 무엇이고 어떻게 활용하나, ③ 수집·큐레이션으로 성능을 어떻게 보일 것인가. 현 우선순위 = **#1·#2 방법론 구현**.

## 0. 먼저 — 진단은 끝났고, 지금 없는 건 "결정 규칙"

Phase 0가 증명한 것은 **P_self(우리 분포) 하나에 대한 진단**이다. 두 렌즈가 같은 결론을 가리킨다:

| 렌즈 | 지표 | 결론 |
|---|---|---|
| ODD(조합) | 2,070/15.36M 관측, top100=86%, `accident/emergency=0`, `occlusion=high` 123 | 조합이 극소수 정상조건에 몰림 |
| 임베딩(벡터) | Effective N 6.0%, Vendi 3.53, Q1 PRUNE 60.5% | 3~4개 의미방향에 집중, 중복 대량 |

문제는 **이 둘 다 "우리 데이터 내부"만 본다는 것**이다. "부족하다"까지는 자기참조로 말할 수 있어도, **"무엇을 얼마나 더 모아야 하나(#1)"와 "무엇은 이미 됐나(#2)"는 외부 기준 없이는 순환**이다(수집량 ≠ 현실노출). 그래서 #1·#2 방법론의 뼈대는 이미 정해져 있다 — **P_self에 두 개의 외부축을 붙이는 것**:

- **exposure (P_ext)** — 현실 노출 빈도 (Phase 1에서 구축 중)
- **criticality** — 안전 심각도 (아직 미착수, 수집과 독립이라 지금 가능)

아래는 이 뼈대 위에서 #1·#2를 "의미있는 방법론"으로 만들려면 실제로 뭐가 채워져야 하는지다.

## 0.5. 두 렌즈: 조건 커버리지(ODD) vs 내용 다양성(임베딩)

> 이 절이 방법론적 novelty의 뿌리다. 두 렌즈가 다르다는 것을 넘어 **왜 구조적으로 상호보완인가**를 증명하면, §1의 "렌즈 화해 2×2"와 #2의 "많다≠충분하다"가 전부 여기서 파생된다. (현 문서에서 §1 결정표가 근거보다 먼저 나오는데, 논리적으로는 이 절이 §1의 전제다.)

### 0.5.1. 원리적 차이 — "두 추정량"이 아니라 "두 facet"

흔한 오해는 *"ODD 다양성과 임베딩 다양성은 같은 '데이터 다양성'을 두 방법으로 잰 것"*이라는 것이다. **아니다.** 둘은 주행로그의 **서로 다른 단면(facet)**을 측정한다:

| | **ODD 렌즈** | **임베딩 렌즈** |
|---|---|---|
| 측정 대상 | **조건**(condition): 어떤 상황에서 달렸나 | **내용**(content): 무슨 장면이 벌어졌나 |
| 수학적 성격 | 이산·명목(nominal), 조합 격자 | 연속·기하(geometric), 밀도/스펙트럼 |
| 정의역 | **전체 공간**(미관측 셀도 정의됨 — `accident=0` 말할 수 있음) | **관측 데이터만**(없는 점은 잴 수 없음) |
| 세밀도 | 셀 **밖**은 봐도 셀 **안**은 못 봄 | 셀 **안**의 연속 변주를 봄 |
| 명명성 | 부족한 것을 **이름으로** 지목(VRU·눈·고폐색) | 방향은 잴 수 있어도 **이름이 없음** |
| 외부 앵커 | 기관 통계(KMA/KTDB)가 이 언어로 말함 → **P_ext 대조 가능** | 외부 대응 분포 없음 → **앵커 불가** |
| 실패 원인 | 태거 오분류(예: national_road=242 아티팩트) | 캡션 문체 + 약한 ODD 민감도(ρ=0.221) |

**가장 날카로운 한 줄**: ODD는 *"어떤 범주가 없는가"*를 재고, 임베딩은 *"있는 범주 안이 얼마나 비었는가"*를 잰다. 이 둘은 원리적으로 겹칠 수 없다 — 하나는 셀의 **부재**, 하나는 셀의 **공허**를 보기 때문.

**왜 ρ=0.221이 "약해서 문제"가 아니라 "이게 논지"인가.** 임베딩은 **캡션**을 인코딩한 것이라 "차량·차선·행동" 같은 **장면 내용**을 주로 담고, ODD 태그는 "날씨·조명·노면" 같은 **메타 조건**을 담는다. 즉 **content ⊥ condition** — 겹침이 약한 게 당연하고, 그게 상호보완의 근거다. ρ=0.221을 *"임베딩이 ODD를 잘 못 잡는다"*로 읽지 말고 *"임베딩은 ODD 스키마에 없는 직교 단면을 추가로 잰다"*로 읽어야 한다.

**결정적 다리 — 임베딩이 exposure의 침묵 축을 부분 복구한다.** exposure 설계(design.md §1)가 스스로 인정한 **C-그룹(측정 불가 축) = occlusion·scene_ambiguity·visibility·lane_marking·junction·unexpected_element** — 어떤 기관도 못 재고 exposure가 침묵하는 축들. 그런데 **캡션 임베딩은 이 C-그룹을 부분적으로 인코딩**할 수 있다("truck에 가려진", "모호한 교차로"). 즉 **임베딩 렌즈는 ODD/exposure가 원리적으로 못 보는 바로 그 축의 대리신호**가 된다. 이것이 "맥락상 상호보완"의 가장 강한 논거다.

### 0.5.2. 상호보완의 구조 — 각자가 상대의 blind spot을 이름으로 메운다

| 진단 질문 | 담당 렌즈 | 상대 렌즈가 못 하는 이유 |
|---|---|---|
| 범주가 **아예 없다**(accident=0, 고폐색 123) | **ODD** | 임베딩은 없는 점을 못 잼(관측만) |
| 있는 셀이 **속이 비었다**(6,578클립인데 Vendi 2.3) | **임베딩** | ODD는 셀 안을 못 봄(카운트만) |
| 현실 대비 **과/소수집**(r=P_self/P_ext) | **ODD+exposure** | 임베딩은 외부 앵커가 없음 |
| **중복** 제거 예산(soft 6% vs hard 56%) | **임베딩** | ODD는 셀 내 near-dup을 못 봄 |
| C-그룹(occlusion·junction 등) 신호 | **임베딩(대리)** | ODD-exposure가 조달 불가로 침묵 |
| **검증**(어느 렌즈가 틀렸나) | **교차 대조** | 단일 렌즈는 자기 오류를 못 봄 |

이 표가 곧 #1·#2의 역할 분담이다: **미관측 안전공간 타겟팅(#1)은 ODD/criticality가**, **셀 내부 충분성·중복 판정(#2)은 임베딩이** 주도.

### 0.5.3. 근거 마련 — 이미 가진 것 vs 채울 것

**상호보완의 증거 대부분을 Phase 0가 이미 만들어놨다.** 논문 작업은 이걸 "argument로 재배열"하는 것에 가깝다.

**이미 손에 있는 증거 (E)**

| # | 증거 | 무엇을 증명 |
|---|---|---|
| E1 | 쌍별 ρ=0.221 (n=10k, p=0) + per-run ρ≈0.2 (n=30, 미유의) | **국소는 약한 양의 정렬, 전역은 사실상 탈구** → 두 요약지표가 다른 것을 잼 |
| E2 | topk per-dim 5↑/2↓ (lighting·road_divider만 ↓) | **축 단위로** 임베딩이 어느 ODD를 반영/무시하는지 지도 |
| E3 | NMI=0.034, ARI=0.011 (TF-IDF 시나리오 × 임베딩 사분면) | 두 분할이 **통계적 독립** → 비중복 정보 |
| E4 | S6·S1(ODD 승격, LID 미검출) vs S9·S7(LID 경계, ODD 낮음) | **한 렌즈가 놓친 걸 다른 렌즈가 잡은 실사례** |
| E5 | top100 ODD=86% **vs** 시나리오 Vendi 2.3~3.0 | "커버리지 초록·다양성 빨강" = **두 렌즈 없이는 진술 불가** |

**채워야 할 증거 (G) — 레버리지 순**

| # | 추가 분석 | 왜 필요 / 무엇을 강화 |
|---|---|---|
| **G1** | **전체 contingency 표**: (ODD-갭 플래그) × (임베딩-갭 플래그)를 12 시나리오(또는 셀) 전수로 교차집계 + 카운트 | S6/S1/S9/S7은 **일화**다. **"두 렌즈가 몇 % 불일치하고 어느 방향인지"** 정량 표로 → 상호보완 주장의 **가장 설득력 있는 단일 산출물** |
| **G2** | ρ=0.221을 **축별로 분해**(축 하나만 변화시킨 조건부 ρ) | "임베딩이 무엇에 눈멀었나"를 **이름으로** 확정 → 그 축은 반드시 ODD로 봐야 한다는 근거 |
| **G3** | **통제된 반례 클립쌍**: ODD-동일·임베딩-먼 쌍 / ODD-다름·임베딩-가까운 쌍을 실제로 꺼내 제시 | 두 렌즈가 다른 걸 잰다는 **정성적 face-validity** |
| **G4** | (egomotion 착지 시) **두 렌즈 결합이 ADE/FDE를 단일 렌즈보다 잘 예측**하는가 | 결정타. "다르다"(기술)→**"둘 다 쓰면 성능예측이 낫다"(예측력)** 로 격상. ODD갭∧임베딩갭 셀이 최악 ADE면 상호보완의 **downstream 증명** |

**G1이 지금 당장 가장 값싸고 강력하다** — Phase 0 산출물(`gap_slices.json`·`quadrant_assignment`·`odd_coverage.json`)만으로 계산 가능하고, 표 하나가 일화 4개를 대체한다.

> ⚠️ **정밀 주의**: E3의 NMI는 **TF-IDF 시나리오 × 임베딩 사분면**이지 **ODD 셀 × 임베딩 사분면**이 아니다. ODD-vs-임베딩 주장에 정확히 대응하는 독립성 통계는 아직 없음 → **G1에서 ODD-셀 분할 × 임베딩 사분면의 NMI/contingency를 직접 계산**해야 페어링이 맞는다.

### 0.5.4. 주장 포인트 (thesis sentences)

1. **구별**: "두 렌즈는 한 양을 두 방법으로 추정한 게 아니라, 주행로그의 직교하는 두 단면 — *조건 커버리지*(ODD)와 *내용 다양성*(임베딩) — 을 잰다."
2. **비중복(경험적)**: "ρ=0.221(국소 약정렬) + NMI≈0.03(전역 독립)은 두 렌즈가 **중복도 잡음도 아닌 대부분 상호보완**임을 정량화한다."
3. **구조적 보완**: "각 렌즈는 상대의 **명명 가능한** blind spot을 메운다 — ODD는 셀 내부 공허에, 임베딩은 미관측 범주·외부앵커·C-그룹 축에 각각 눈먼다."(§0.5.2 표)
4. **payoff**: "두 헤드라인이 이 융합에서만 나온다 — (a) *'많다≠충분하다'*(#2)는 어느 단일 렌즈로도 진술 불가, (b) *수집/합성/무시 2×2 결정*(#1)은 두 플래그를 동시에 요구." (+G4 착지 시: 융합이 모델오차를 더 잘 예측)
5. **검증(정직한 한계 포함)**: "두 렌즈는 추출 방식이 달라(이산 태깅 vs 연속 인코딩) 불일치가 실패를 국소화한다. **단, 둘 다 캡션에서 파생되므로 상류 캡션 오류는 공유** — 진짜 독립 검증은 제3 신호(egomotion/센서)를 요한다."(이 한계 명시가 오히려 신뢰도를 올림)

### 0.5.5. 실증 결과 — 개념에서 관측으로 (`phase0/analysis_two_lens.py`)

세 분석으로 §0.5의 주장을 상관계수가 아니라 **구성적 측정**으로 확정. 재현: `../../analysis_two_lens.py`(시드 고정).

**실증① — ODD 셀 고정 → 임베딩.** 가장 흔한 ODD 조합 6,578클립(ODD entropy=0)의 셀 내부 임베딩 Vendi=**3.17** = 무작위 동일크기(3.53)의 **89.9%**. 임베딩∼ODD였다면 Vendi→1이어야 → **임베딩 방향 ⊥ ODD 셀**(임베딩=노이즈설 반박).

**실증② — 임베딩 이웃 고정 → ODD.** 임베딩 20-NN(코사인 0.939)의 ODD Hamming 0.162 vs 무작위 0.293 = **55.3% 보존**; 코사인>0.95 이웃묶음이 평균 **6.85개 ODD 셀**에 걸침.

**실증③ — top 셀의 혼동 구조 (기저율 통제).**
- **Lift**: same-combo 20-NN 18.0% vs 기저율 6.6% = **2.7×**(약한 정렬 — 최근접의 81%는 다른 조합). 셀이 임베딩상 흩어져 있다는(실증①) 예측과 정합.
- **필드-flip 분포**: 0필드 18% / 1필드 35% / 2필드 31% / 3+필드 15% → 임베딩은 **인접 셀로 샌다**(먼 곳 아님).
- **축별 flip율** (다른 조합 이웃에서 각 축이 top 셀과 갈리는 비율 — 높을수록 임베딩이 무시):

| ODD 축 (top 셀 값) | flip율 | 판정 |
|---|---|---|
| junction_proximity (post_junction) | **49.7%** | 임베딩 blind |
| lighting (well_lit) | **49.1%** | 임베딩 blind — topk per-dim(↓2축)에서 독립 재확인 |
| road_type (urban) | **35.8%** | 임베딩 약blind |
| traffic_density (sparse) | **35.0%** | 임베딩 약blind |
| agent_type (cars_only) | 3.6% | ⚠ 퇴화축(97% cars_only) |
| visibility_range (good) | 3.5% | ⚠ 퇴화축 |
| road_surface (dry) | 3.0% | ⚠ 퇴화축 |
| lane_marking_quality (clear) | 1.5% | ⚠ 퇴화축 |
| weather (clear) | 0.8% | ⚠ 퇴화축(92% clear) |
| occlusion_level (low) | 0.1% | ⚠ 퇴화축(99% low) |
| special_event (none) | 0.0% | ⚠ 퇴화축(~100% none) |

- **강한 결론(상위 4축)**: junction·lighting·road_type·traffic은 데이터에 **변량이 충분한데도** 임베딩이 자유 교차 → **ODD가 담고 임베딩이 잃는 정보. 이 축은 반드시 ODD로 봐야 함**(임베딩 검색·큐레이션 단독은 놓침). lighting은 topk per-dim의 임베딩-미반영 2축과 **독립 재확인**(삼각검증).
- **⚠️ 하위 축 caveat**: weather·occlusion·special_event 등의 낮은 flip은 "임베딩이 존중"이 **아니라** 데이터 퇴화(그 축이 거의 상수 → 바꿀 값 없음). base-rate confound의 축별 버전이라 **"임베딩이 이 축을 잘 잡는다"고 결론 불가.**

**실증④ — η²(전체 분산 분해). "ODD가 임베딩을 몇 % 설명하나"의 엄밀 전체값.**
- 방법: 임베딩 다양성을 분산으로 놓고 `η² = 셀-간 분산(SS_between) / 전체 분산(SS_total)` = 각 ODD 셀을 한 점으로 뭉쳤을 때 남는 분산 비율. 셀 2,070개(싱글톤 다수)라 무작위 그룹도 우연히 설명 → **순열 귀무로 보정**.
- 결과: η² 관측 **21.3%** / 순열귀무 **2.1%**(인플레 작음) / 보정 **19.6%** / ≥50클립 셀(169개) **18.7%** → 일관되게 **ODD는 임베딩 분산의 ~20%만 설명, ~80%가 ODD 밖.**
- **⚠️ 실증①의 단일-셀 값(90% 잔존)이 직교성을 과장했음을 교정**: top 셀은 '정상조건'이라 ODD 분리력이 **평균 이하**여서 within 잔존율이 유독 높았던 것. **전체 엄밀값은 80% 밖(90% 아님)**. 그래도 80% 잔차 = 상호보완 논지는 강하게 유지.

> 위 표들이 §0.5.3의 **G1(전수 contingency)·G2(축별 정렬 분해)**, 실증④가 **"ODD 설명률"의 엄밀 전체 수치**를 실현한 것. 남은 G4(모델오차 예측 payoff)는 egomotion 착지 후.

## 1. 방법론 #1 — "무엇을 수집할까"

### 목표 수식은 이미 확정됨
```
최종 수집타겟 = (exposure 누적 95% 영역) ∪ (criticality 상위 희귀-위험 조합)
              그중 P_self 과소수집(under-collected)인 것
```
coverage-vs-sufficiency Q1-B와 phase1 §8~§10이 정식화. 문제는 **세 재료의 성숙도가 제각각**이다:

| 재료 | 상태 | 병목 |
|---|---|---|
| **exposure P_ext** | 구현됨(compose.py, P_ext.json 12셀) | ⚠️ **road_type 2/4뿐** (highway·national_road만; KTDB가 지방도·국지도 502). **데이터의 84%인 urban/rural에 외부앵커가 없음** |
| **criticality** | 미착수 | 없음 — 손 위험표라 **지금 바로 만들 수 있음** |
| **under-collected(P_self)** | 구현됨(gap_slices, collect_candidates) | 축 정합(§12-R): fog·speed·unknown |

### 핵심 방법론적 기여가 될 지점 — "두 렌즈의 화해"

논문의 알맹이가 될 부분. Phase 0의 `collect_candidates.json`이 이미 예시를 보여준다:

> **S6·S1은 임베딩(LID) 기준으론 단조(mean_lid<16.86)라 안 걸리는데, ODD 다양성(≥22)으로 승격됐다.** 반대로 S9/S7은 LID는 경계인데 ODD가 낮아 합성으로 갔다.

즉 **ρ=0.221(partial alignment)** 이라 임베딩 렌즈 단독은 ODD 갭을 놓치고, ODD 렌즈 단독은 셀 내부 구조를 놓친다. **"어느 렌즈에서 부족으로 뜨는가"에 따라 수집 vs 합성 vs 무시가 갈린다** — 이 2×2 결정표가 방법론이다:

```
ODD갭 O × 임베딩갭 O → 실수집 최우선 (S10, S11)
ODD갭 O × 임베딩갭 X → 실수집 (조건은 다양, 장면표현은 단조 — S6, S1)
ODD갭 X × 임베딩갭 O → 합성 후보 (장면은 다양, 조건축은 이미 있음 — S9, S7)
ODD갭 X × 임베딩갭 X → 무시 (이미 충분하거나 중요치 않음)
```

여기에 exposure(현실빈도)와 criticality(위험)를 **곱의 가중**으로 얹으면 `priority = criticality × exposure × (렌즈 부족도)`가 된다.

### #1을 "의미있게" 만들려면 반드시 채울 것 두 개

1. **criticality 손 위험표 (§10)** — 지금 착수. `accident/emergency=0`·`occlusion=high`·VRU 극소 같은 **안전 꼬리는 exposure가 원리적으로 못 잡는다**(희귀 = 저빈도 = 누적 하위). 이 축이 없으면 "정상조건만 더 모으자"는 무의미한 결론으로 흐른다. published multiplier 앵커(보행자 4×, 눈 2.5×, speed high 4× 등)로 값 정당화 — 클립 불필요, **오늘 만들 수 있는 유일한 full-space 축**.
2. **urban/rural exposure 조달 (P0 데이터작업)** — P_ext가 head 축(84%)을 못 덮으면 P_self 대조가 head에서 성립하지 않는다. 지방도/도시부 VKT·agent 조달이 #1의 진짜 1순위 병목(REVIEW E1의 national_road=242 아티팩트 의심도 여기 걸림).

## 2. 방법론 #2 — "무엇은 충분한가 + 어떻게 쓸까"

### 가장 중요한 재프레이밍: "충분히 확보" ≠ "많이 확보"

Phase 0의 결과는 정확히 그 함정을 경고한다:

- top100 조합 = 86% (양은 압도적) ← **abundant**
- 그러나 시나리오별 Vendi 2.3~3.0, Effective N 6%, `agent_type effective_n=1.16` ← **NOT diverse**

즉 **"많이 확보된 셀"과 "충분히 확보된 셀"은 다르다.** 커버리지 표는 초록불인데 신뢰성은 빨간불(coverage-vs-sufficiency Q2). 그래서 #2 방법론의 첫 단계는 **"충분"의 조작적 정의**다 — 세 관문을 다 통과해야 충분:

```
셀 c가 "충분" ⟺  (A) 셀 내부 다양성 effective_n/Vendi ≥ 임계   (있음: 재사용)
             ∧  (B) 성능 포화곡선이 평평   a(1−e^{−n/τ})       (없음: 병목)
             ∧  (C) 셀 내부분포가 현실과 정합 MMD/KL           (부분)
```

이 정의를 적용하면 "충분히 확보된 케이스"는 아마 **맑음×도심/지방×주간×차량만×저밀도** 몇 개 head 셀로 좁혀진다. 그게 논문의 정직한 답이다: *"10만 클립이지만 실제로 충분한 건 소수 정상조건뿐"*.

### 그 데이터를 "어떻게 활용"하나 — 세 갈래

1. **Pruning / Coreset** — Q1 PRUNE 60.5%(60,731클립)가 대상. SoftDedup 진단이 이미 나와 있음(soft 6% vs hard 56% = 회색지대 중복 대량). **Coverage-centric Coreset(기하 set-cover) 또는 Sorscher 기하 프루닝**으로 head 중복을 버리되 다양성은 보존 → 학습셋 축소·예산 확보. 이게 #3 첫 성능실험으로 직결(“X% 예산으로 동등 성능”, MOSAIC BRMR 0.18류).
2. **Reweighting** — 버리는 대신 학습 손실에서 head를 다운웨이트. RoCA의 **GP-variance 기반 불확실성 가중**이나 `1/P_self` inverse-frequency가 직접 후보. 롱테일에 자동으로 가중이 실림.
3. **Anchor(기준선)** — 충분(포화)한 head는 버리는 게 아니라 **스케일링 논증의 기준선**이다. "이 셀에 더 넣어도 안 오른다"(Naumann: 5%개선=+273,000h)를 보여주는 대조군 = #3의 논거.

### #2를 "의미있게" 만들려면 채울 것
- (A) 셀 내부 다양성: **이미 있음**(effective_n·Vendi를 per-target-cell로 돌리면 됨).
- (B) 성능 포화곡선: **없음. 이게 #2와 #3 공통 병목** ↓

## 3. 두 방법론을 동시에 여는 linchpin — per-clip 성능 대리지표

#1의 Domino 2×2(밀도×성능)도, #2의 포화곡선 정지판정도, #3의 성능 시연도 **전부 "이 클립/셀에서 모델이 실제로 실패하나(model_sensitivity)"** 를 요구한다. 이게 지금 유일하게 비어 있는 축이다.

wiki가 이미 저비용 경로를 지목한다(coverage-vs-sufficiency Step 4):
> **egomotion surrogate** — `egomotion_offline` ego궤적을 GT로 "과거→미래 궤적 예측" → **라벨 없이 per-clip ADE/FDE**. 착수 전 10줄로 GT 사용성(커버율·품질·프레임 정합)부터 확인(de-risk).

이 하나가 서면:
- **#1**: `low-density × low-perf` = 최우선 수집 (Domino 완성)
- **#2**: 셀별 ADE/FDE를 데이터량에 대해 그리면 포화곡선 = 정지판정 (B관문 완성)
- **#3**: 그대로 성능 시연 (수집/큐레이션 전후 ADE/FDE)
