# Phase 0 기반 방법론 — 성능 지향 데이터 획득 가이드 (guided acquisition)

> **성격**: Phase 0 진단(`results_interpretation.md`) + phase0_2 exposure 설계(`../../phase0_2/design.md`, `../../phase0_2/exposure/REVIEW.md`) + 개념틀(`docs/wiki/evaluation/coverage-vs-sufficiency.md`)을 종합해, **"1000개를 어떻게 골라 수집하면 모델 성능이 가장 오르나"**의 가이드를 ODD×임베딩으로 만드는 방법론 노트. (성능 신호 = phase1 egomotion ADE/FDE.)
>
> **연구 목표(재정의)**: 가진 데이터를 **효율적으로 수집하여 성능을 높인다**. 구체적으로 — 추가 예산 ~1000클립을 어디에 쓸지 랭킹하는 **획득 가이드**를 두 렌즈(ODD·임베딩)+외부축(exposure·criticality)+성능신호(egomotion)로 산출하고, 그것이 실제로 성능을 올림을 **leave-out 재현실험**으로 증명한다.
>
> **연구 질문 3개**: ① 무엇을 수집해야 성능이 오르나(획득 가이드), ② 무엇은 이미 충분해 수집 불필요한가(무시·프루닝), ③ 수집·큐레이션 전후로 성능을 어떻게 보이나(검증).

---

## 0. 근본 함정 — 이건 "가이드형 데이터 획득" 문제다

Phase 0가 증명한 것은 **P_self(우리 분포) 하나에 대한 진단**이다. 두 렌즈가 같은 결론을 가리킨다:

| 렌즈 | 지표 | 결론 |
|---|---|---|
| ODD(조합) | 2,070/15.36M 관측, top100=86%, `accident/emergency=0`, `occlusion=high` 123 | 조합이 극소수 정상조건에 몰림 |
| 임베딩(벡터) | Effective N 6.0%, Vendi 3.53, Q1 PRUNE 60.5% | 3~4개 의미방향에 집중, 중복 대량 |

**함정**: *"아직 수집 안 한 1000개의 성능 기여는 관측 불가능하다."* 그러니 어떤 방법론도 "성능이 오른다"를 직접 최적화할 수 없고, **대리 신호로 예측 → 사후 검증**하는 구조여야 한다. 이걸 인정하지 않으면 **coverage(커버리지 채우기)를 performance(성능)로 착각**하는 함정(coverage-vs-sufficiency Q2)에 빠진다. 그래서 방법론은 두 층:

- **(가이드층, §2~§4)** 어디를 수집할지 점수화하는 **획득함수** — ODD×임베딩×exposure×criticality×model_error.
- **(검증층, §5)** 그 가이드가 실제로 성능을 올린다는 걸 **기존 10만 데이터의 leave-out 재현실험**으로 증명 → 정책을 실제 1000클립 수집에 이관.

또한 두 렌즈 다 **"우리 데이터 내부"만 본다** — "부족하다"는 자기참조로 말해도, "무엇을 얼마나 더(§2)"·"무엇은 이미 됐나(§4)"는 외부 기준 없이는 순환이다. 그래서 P_self에 **두 외부축**을 붙인다: **exposure(P_ext, 현실빈도)** · **criticality(안전 심각도)**.

## 1. 두 렌즈 — 왜 조합해야 하나 (획득함수의 근거)

> 이 절이 방법론적 novelty의 뿌리다. 두 렌즈가 **왜 구조적으로 상호보완인가**를 증명하면, §2 획득함수의 "각 인자를 어느 렌즈가 담당하나"와 §3의 수집/합성/무시 2×2가 전부 여기서 파생된다.

### 1.1. 원리적 차이 — "두 추정량"이 아니라 "두 facet"

흔한 오해는 *"ODD 다양성과 임베딩 다양성은 같은 '데이터 다양성'을 두 방법으로 잰 것"*이다. **아니다.** 둘은 주행로그의 **서로 다른 단면(facet)**을 측정한다:

| | **ODD 렌즈** | **임베딩 렌즈** |
|---|---|---|
| 측정 대상 | **조건**(condition): 어떤 상황에서 달렸나 | **내용**(content): 무슨 장면이 벌어졌나 |
| 수학적 성격 | 이산·명목(nominal), 조합 격자 | 연속·기하(geometric), 밀도/스펙트럼 |
| 정의역 | **전체 공간**(미관측 셀도 정의됨 — `accident=0` 말할 수 있음) | **관측 데이터만**(없는 점은 잴 수 없음) |
| 명명성 | 부족한 것을 **이름으로** 지목(VRU·눈·고폐색) | 방향은 잴 수 있어도 **이름이 없음** |
| 외부 앵커 | 기관 통계(KMA/KTDB)가 이 언어로 말함 → **P_ext 대조 가능** | 외부 대응 분포 없음 → **앵커 불가** |
| 실패 원인 | 태거 오분류(예: national_road=242 아티팩트) | 캡션 문체 + 약한 ODD 민감도(ρ=0.221) |

**가장 날카로운 한 줄**: ODD는 *"어떤 조건이 없는가(부재)"*를 재고, 임베딩은 *"가진 데이터가 실제로 몇 방향으로 다른가(실질 다양성)"*를 잰다. 관계는 *중첩(nested)*이 아니라 **직교(orthogonal)** — 같은 셀의 밖/안이 아니라, 같은 데이터의 서로 다른 두 분할(격자 vs 기하)이다.

> ⚠️ **"셀 안 공허"는 정의가 아니라 파생 연산.** 임베딩을 특정 ODD 셀에 **조건화했을 때**(실증①: 셀 고정 → 셀 내부 Vendi)만 "범주 안"이 성립한다. 임베딩 렌즈의 *native* 연산(전역 Vendi·kNN·Effective N)은 셀 분할을 안 보므로, "임베딩=범주 안을 잰다"로 정의하면 실증②③④(lift 2.7×·NN 11조합·η² 80% 셀밖)와 모순된다.

**왜 ρ=0.221이 "약해서 문제"가 아니라 "이게 논지"인가.** 임베딩은 **캡션**을 인코딩한 것이라 "차량·차선·행동" 같은 **장면 내용**을, ODD 태그는 "날씨·조명·노면" 같은 **메타 조건**을 담는다. 즉 **content ⊥ condition** — 겹침이 약한 게 당연하고, 그게 상호보완의 근거다.

**결정적 다리 — 임베딩이 exposure의 침묵 축을 부분 복구한다.** exposure 설계(design.md §1)가 인정한 **C-그룹(측정 불가 축) = occlusion·scene_ambiguity·visibility·lane_marking·junction·unexpected_element** — 기관이 못 재고 exposure가 침묵하는 축들. 그런데 **캡션 임베딩은 이 C-그룹을 부분적으로 인코딩**한다("truck에 가려진", "모호한 교차로"). 즉 임베딩은 ODD/exposure가 원리적으로 못 보는 축의 **대리신호**다.

### 1.2. 상호보완의 구조 — 각자가 상대의 blind spot을 이름으로 메운다

| 진단 질문 | 담당 렌즈 | 상대 렌즈가 못 하는 이유 |
|---|---|---|
| 범주가 **아예 없다**(accident=0, 고폐색 123) | **ODD** | 임베딩은 없는 점을 못 잼(관측만) |
| 있는 셀이 **속이 비었다**(6,578클립인데 Vendi 3.17) | **임베딩** | ODD는 셀 안을 못 봄(카운트만) |
| 현실 대비 **과/소수집**(r=P_self/P_ext) | **ODD+exposure** | 임베딩은 외부 앵커가 없음 |
| **중복** 제거 예산(soft 6% vs hard 56%) | **임베딩** | ODD는 셀 내 near-dup을 못 봄 |
| C-그룹(occlusion·junction 등) 신호 | **임베딩(대리)** | ODD-exposure가 조달 불가로 침묵 |
| **검증**(어느 렌즈가 틀렸나) | **교차 대조** | 단일 렌즈는 자기 오류를 못 봄 |

**이 표가 곧 §2 획득함수의 역할 분담이다** — 미관측 안전공간 타겟팅은 ODD/criticality가, 셀 내부 충분성·중복 판정은 임베딩이 주도.

### 1.3. 실증 결과 — 개념에서 관측으로 (`phase0/analysis_two_lens.py`, 시드 고정)

네 분석이 §1.1~1.2의 주장을 상관계수가 아니라 **구성적 측정**으로 확정했다.

- **실증① — ODD 셀 고정 → 임베딩.** 가장 흔한 ODD 조합 6,578클립(ODD entropy=0)의 셀 내부 임베딩 Vendi=**3.17** = 무작위 동일크기(3.53)의 **89.9%**. 임베딩∼ODD였다면 Vendi→1이어야 → **임베딩 방향 ⊥ ODD 셀**. (셀 내부 서브클러스터를 TF-IDF로 명명: `정차·노변주차`3,163 vs `교차로 통과주행`3,415 — ODD엔 없는 **기동 축**.)
- **실증② — 임베딩 이웃 고정 → ODD.** 임베딩 20-NN(평균 유사도 0.94)의 ODD Hamming 0.162 vs 무작위 0.293 = **55.3% 보존**; 같은 상위 20 이웃 묶음이 평균 **~11개 ODD 조합**에 걸침.
- **실증③ — top 셀 혼동 구조.** same-combo 20-NN **lift 2.7×**(18% vs 기저율 6.6% — 최근접의 81%가 다른 조합). **축별 flip율**: junction 49.7%·lighting 49.1%·road_type 35.8%·traffic 35.0% → 이 4축은 **변량이 충분한데도 임베딩이 자유 교차 → 반드시 ODD로 봐야 함**(임베딩 검색 단독은 놓침). 하위 축(weather·occlusion 등)의 낮은 flip은 "임베딩 존중"이 아니라 **데이터 퇴화**(base-rate confound)라 결론 불가.
- **실증④ — η²(전체 분산 분해).** ODD 셀 소속이 임베딩 분산을 몇 % 설명하나: 관측 **21.3%** · 순열귀무 **2.1%**(인플레 작음 ✓) · 보정 **19.6%** · ≥50클립 169셀 **18.7%** → 세 방식 ~20% 수렴. **ODD는 임베딩 분산의 ~20%만 설명, ~80%가 ODD 밖** = 상호보완의 정량 증거. (실증①의 "90% 잔존"은 정상조건 셀 편향 → 전체 엄밀값 80%로 교정.)

**주장 포인트(thesis)**: (1) 두 렌즈는 한 양의 두 추정이 아니라 직교하는 두 단면이다. (2) ρ=0.221(국소 약정렬)+NMI≈0.03(전역 독립)은 두 렌즈가 **대부분 상호보완**임을 정량화. (3) 각 렌즈가 상대의 **명명 가능한** blind spot을 메운다. (4) **payoff — "많다≠충분하다"와 수집/합성/무시 결정은 두 렌즈 동시에만 진술 가능**(§5 G4가 성능으로 증명). (5) 정직한 한계 — 둘 다 캡션 파생이라 상류 오류 공유 → 진짜 독립검증은 제3 신호(egomotion).

## 2. 획득함수 — 다섯 신호의 곱

각 후보 타깃 `c`(=ODD 셀)에 대해:

```
Priority(c) = criticality(c) × exposure(c) × deficit(c) × model_error(c) × headroom(c)
                └─가치─┘        └─현실빈도─┘   └─부족도─┘      └─성능신호─┘     └─다양성여지─┘
```

각 인자가 **어느 렌즈에서 나오는지**가 두 렌즈 조합의 핵심이다:

| 인자 | 의미 | 담당 | 현 상태 |
|---|---|---|---|
| **criticality(c)** | 안전 심각도(사고·VRU·고폐색) | ODD(full-space) | ❌ 미착수 — **오늘 만들 수 있음** |
| **exposure(c)** | 현실 노출빈도 P_ext | ODD+기관통계 | ⚠️ road_type 2/4만(highway·national_road) |
| **deficit(c)** | 과소수집 r=P_ext/P_self, 또는 부재 | ODD(부재는 ODD만 앎) | ✅ gap_slices |
| **model_error(c)** | 이 조건에서 모델이 실제 틀리나 | **egomotion ADE/FDE** | ❌ **진짜 병목** |
| **headroom(c)** | 더 넣으면 새 내용? 중복? | **임베딩(Vendi/EffN)** | ✅ |

**두 렌즈의 역할이 여기서 갈린다:**
- **ODD = *어느 셀*을 지목** — 부재·과소수집·심각도는 이름 있는 조건축에서만 나온다. 수집 발주는 이름으로 하므로 **수집 단위는 반드시 ODD 셀**.
- **임베딩 = *그 셀을 채우는 게 값어치 있나*를 판정(headroom)** — 이미 임베딩상 포화(near-dup)면 1000개 부어도 성능이 안 오른다. 임베딩은 "수집해도 새 정보 없는 셀"을 걸러 **예산 낭비를 막는 게이트**.

**획득함수의 이론적 정당화**: 어떤 region `c`에 클립을 더해 얻는 기대 위험감소는 대략
`ΔRisk(c) ≈ w(c)·e(c)·g(n_c)` — `w(c)`=배포 중요도(=exposure×criticality), `e(c)`=현 모델오차(=model_error), `g(n_c)`=현재 보유량 `n_c`에서의 한계이득(=headroom·포화도). Priority는 이 세 항의 조작적 구현이다.

## 3. 수집 단위 = ODD 셀 · 임베딩 = 서브타깃 + 중복 게이트

ODD 셀 하나를 골라도 그 **안에서 무엇을** 수집할지는 ODD가 못 말한다(셀 안 못 봄). 여기서 임베딩이 결정적:

> **ODD 셀 → 임베딩 서브클러스터 → TF-IDF 대표어 → 발주 가능한 서브타깃**

실증①이 이미 방법을 보였다(셀을 `정차` vs `통과주행`으로 갈라 명명). "임베딩은 이름이 없다"는 한계를 **TF-IDF가 메워** 최종 산출물이 발주서가 된다:

```
수집 스펙 예시 (1개 항목)
  ODD 셀: urban × rain × night × VRU × moderate-density
  현재 보유: 40클립 (임베딩상 3방향 중 '직진 접근'만 밀집)
  결핍 서브타깃: '횡단보도 정지', '우회전 중 보행자' (TF-IDF, 현재 0)
  목표 수량: 120 (포화곡선상 marginal gain 큰 구간)
  근거: criticality 4× · exposure 상위 · model_error 상위 15% · headroom 큼
```

**수집 vs 합성 vs 무시 2×2** (어느 렌즈에서 부족으로 뜨는가로 라우팅 — collect_candidates의 S6/S1 vs S9/S7이 축소판):

```
ODD갭 O × 임베딩갭 O → 실수집 최우선   (S10·S11)
ODD갭 O × 임베딩갭 X → 실수집          (조건 다양·장면 단조 — S6·S1)
ODD갭 X × 임베딩갭 O → 합성 후보        (장면 다양·조건축 이미 있음 — S9·S7)
ODD갭 X × 임베딩갭 X → 무시            (이미 충분하거나 중요치 않음)
```

## 4. 예산 배분 — "효율적으로"의 실체

1000개를 랭킹 상위에 몰아넣는 건 비효율. **셀별 한계효용**을 본다:

- 셀 `c`의 성능 포화곡선 `perf(n)=a(1−e^{−n/τ})`을 leave-out 실험으로 추정.
- 한계이득 `dperf/dn ∝ e^{−n/τ}` → **포화 근처 셀은 캡, 가파른 셀에 배분**.
- 배분: `alloc(c) ∝ Priority(c)×marginal_gain(c)`, 총합 1000 제약.

**핵심 효율 원칙 — 수집 전에 공짜 옵션부터 소진** (1000 예산은 마이닝·합성으로 도달 불가능한 셀에만):

| 셀 상태 | 처방 | 이유 |
|---|---|---|
| 완전 부재 (accident=0, 고폐색 근처) | **수집**(예산 사용) | 마이닝·합성 불가 |
| 있으나 희소 tail | **먼저 기존 10만서 마이닝/증강** → 그래도 부족하면 수집 | 공짜 |
| 있으나 중복 head (soft dedup 6%) | **프루닝**(Q1 PRUNE 60.5%) — 수집 대상 아님 | 예산 낭비 |

**"충분"의 조작적 정의**(=무시/프루닝 판정 = 옛 #2) — 세 관문 통과해야 충분: (A) 셀 내부 다양성 effective_n/Vendi ≥ 임계(있음) ∧ (B) 성능 포화곡선 평평(§4 곡선) ∧ (C) 셀 내부분포 현실 정합 MMD/KL(부분). 이 정의를 적용하면 "충분"은 맑음×도심/지방×주간×차량만×저밀도 몇 head 셀로 좁혀진다 — 그게 정직한 답("10만이지만 실제 충분한 건 소수 정상조건뿐").

## 5. 검증층 — leave-out 재현실험 (논문의 척추)

실제 1000개 수집 *전에* 정책이 옳음을 기존 데이터로 증명:

1. 10만에서 특정 tail 셀을 **인위적으로 제거**해 "결핍 학습셋" 생성.
2. 모델 학습 → baseline ADE/FDE.
3. 제거분을 **정책별로** 다시 "획득":
   (a) **guided**(제안 획득함수) · (b) random · (c) coverage-only(ODD 부재만) · (d) uncertainty-only(model_error만) · (e) diversity-only(임베딩만).
4. 각각 N개 되메워 재학습 → **ADE/FDE 회복량 / 클립** 비교.

**핵심 결과 두 개:**
- **guided > 나머지 전부** → 정책 유효 → 실제 1000 수집에 이관 가능.
- **guided(ODD+임베딩) > ODD-only, 임베딩-only** → **두 렌즈 상호보완의 downstream 증명(G4)**. "다르다(기술)" → "둘 다 쓰면 성능예측이 낫다(예측력)"로 격상. **이 한 장이 논문의 결정타.**

**수집한 데이터의 활용(옛 #2 세 갈래)**: ① Pruning/Coreset(Q1 PRUNE 60,731 — SoftDedup 진단 기존; Coverage-centric coreset/Sorscher 기하 프루닝) · ② Reweighting(RoCA GP-variance 불확실성 가중, 또는 1/P_self) · ③ Anchor(포화 head는 "더 넣어도 안 오른다"의 대조군 — Naumann 5%개선=+273,000h).

## 6. 채울 것 (재사용 우선, 새 프레임워크 금지) — 착수 순서

| 순 | 작업 | 상태 | 이게 없으면 |
|---|---|---|---|
| **1** | **egomotion ADE/FDE per-clip 대리지표** (→ **phase1/**) | ✅ **GT de-risk GO** · 구현 중 | model_error 부재 → "성능 가이드"가 "커버리지 가이드"로 전락. #2·#3 공통 관문. **de-risk 결과**: 커버율 97.4%(97,820/100,398) · 6-DoF 포즈 ~10Hz·20s · 2+3s 지평 100% 확보 (`phase0/derisk_egomotion.py`) |

| **3** | **leave-out 실험 하네스** | ❌(소량) | 검증층 전체 = 논문 성립 여부 |

**진짜 병목은 단 하나였던 #1 egomotion 대리지표 — GT de-risk 통과(GO)로 해소.** 이제 구현만 남았고(→ **phase1/**), 이게 서면 획득(§2)·충분성(§4)·성능시연(§5)이 동시에 열린다.

## 7. 정직한 한계 (명시하면 오히려 신뢰↑)

- ADE/FDE는 egomotion 궤적 대리지 진짜 태스크 손실이 아님 → "성능"의 조작적 정의를 이걸로 고정한다고 선언.
- ODD·임베딩 **둘 다 캡션 파생** → 상류 캡션 오류 공유. 단 검증층의 model_error(egomotion=센서 기반)는 **캡션과 독립인 제3 신호**라 이 검증이 그 약점을 보완.
- η² 결과 신뢰도는 **귀무 2.1%가 낮다**는 데 달림 — 귀무가 15~20%였다면 관측 20%는 싱글톤 아티팩트로 무너짐. 발표 방어선.
- 실제 1000 수집엔 대조군(random 1000) 확보가 이상적 — 예산 되면 소량이라도.

## 한 줄 결론

획득함수 `criticality×exposure×deficit×model_error×headroom`에서 **ODD가 '어느 셀'을, 임베딩이 'TF-IDF 서브타깃+중복 게이트'를** 맡고 **egomotion ADE/FDE가 성능 신호**를 공급한다. 이를 **leave-out 재현실험으로 guided > 단일렌즈**로 보이면 곧 두 렌즈 상호보완의 성능 증명이다. 방법론 뼈대와 대부분 코드는 이미 있고(gap_slices·collect_candidates·P_ext·effective_n·실증①~④), 마지막 병목이던 **egomotion 대리지표는 GT de-risk 통과(97.4% 커버·6-DoF·10Hz)로 GO** → phase1에서 구현 착수.
