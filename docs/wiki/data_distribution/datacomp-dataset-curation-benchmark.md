## 핵심 아이디어

모델 아키텍처와 학습 코드를 고정하고 **데이터 큐레이션 전략만을 경쟁 변수**로 설정한 대규모 벤치마크.  
1.28B 이미지-텍스트 쌍(CommonPool)에서 다양한 필터링·샘플링 전략을 38개 다운스트림 평가 태스크로 비교하며, 핵심 결론은 "**품질 필터링 먼저, 다양성 인식 샘플링 그 다음**" 순서가 최선임.  
롱테일/희귀 카테고리 성능에는 다양성 보장이 필수적이지만, 다양성만 추구하면 평균 성능이 하락할 수 있음을 정량적으로 입증.

### 핵심 발견 3가지

**발견 1 — 필터링 우선:**
```
품질 필터링(CLIP score, 텍스트 품질, 중복 제거)이
다양성 샘플링보다 평균 성능 향상에 더 효과적
→ 필터링으로 노이즈를 제거하면 다양성 전략 효과가 극대화됨
```

**발견 2 — 롱테일 보호:**
```
다양성 보장 없는 순수 필터링은 희귀 카테고리 성능 하락
→ 필터 후에도 특정 시나리오의 샘플이 0에 수렴하는 문제
→ 다양성 인식 샘플링으로 롱테일 커버리지 별도 확보 필요
```

**발견 3 — 최적 전략 순서:**
```
Step 1: 품질 필터 (CLIP score 임계값, 텍스트 길이, 중복 제거)
Step 2: 다양성 인식 샘플링 (클러스터 기반, 희귀 슬라이스 오버샘플링)
↑ 이 순서가 반대 순서 또는 단독 사용보다 모든 평가에서 우수
```

### 실험 스케일 및 구조

| 트랙 | 데이터 풀 크기 | 큐레이션 전략 수 |
|------|--------------|---------------|
| Small | 12.8M pairs | 60+ 전략 |
| Medium | 128M pairs | 40+ 전략 |
| Large | 1.28B pairs | 20+ 전략 |
| BYOD (외부 데이터) | 제한 없음 | 자유 형식 |

### 전략별 성능 비교 (Medium 트랙, ImageNet 정확도)

| 큐레이션 전략 | ImageNet Acc | 38-task 평균 |
|-------------|--------------|-------------|
| 무작위 샘플링 | 17.5% | 24.1% |
| CLIP score 필터링만 | 24.2% | 31.5% |
| 다양성 샘플링만 | 20.1% | 27.3% |
| **필터링 → 다양성 샘플링** | **27.8%** | **34.9%** |

## 장단점

**장점**
- 엄밀한 통제 실험 설계: 모델 고정 → 데이터 효과만 순수하게 측정
- 38개 다양한 평가 태스크 → 특정 태스크 과적합 방지
- 1.28B 대규모 풀 → 실용적 스케일에서의 검증
- BYOD 트랙 → 외부 도메인 특화 데이터의 전략도 포함

**단점**
- CLIP 기반 필터링에 의존 → CLIP이 약한 도메인(AV 특화 시나리오)에서 기준 불명확
- 이미지-텍스트 페어 기준으로 설계 → 비디오 클립 데이터에 직접 적용 시 수정 필요
- 38개 태스크 평균 최적화 → 특정 희귀 시나리오 최적화와 목표가 다를 수 있음
- CommonPool은 웹 크롤 데이터 기반 → 자율주행 도메인과 다른 노이즈 특성

## 프로젝트 적용 포인트

### Gap-4 연결

DataComp의 "필터링 먼저 → 다양성 샘플링 순서" 원칙이 AV 데이터 큐레이션에 직접 적용됨.  
단순히 희귀 시나리오를 추가하기 전에, **먼저 저품질 클립을 제거**하는 것이 더 효과적이라는 실험적 근거 제공.

**AV 데이터 큐레이션 파이프라인 (DataComp 원칙 적용):**
```
Phase 0: 품질 필터링
  → 짧은 캡션 클립 제거 (캡션 길이 < 임계값)
  → 중복 클립 제거 (임베딩 유사도 > 임계값)
  → 라벨 오류 클립 제거 (SANFlow 밀도 이상치)

Phase A: 다양성 인식 샘플링
  → 야간/우천/교차로 클러스터 오버샘플링
  → 밀도 하위 슬라이스 우선 보충
  → 필터링으로 확보된 슬롯을 갭 시나리오에 배정
```

**기대 효과**: Phase 0 필터링 후 Phase A를 적용하면, Phase A만 단독 적용 대비 Recall@5 추가 향상.

### EXP-003 / EXP-004 연계 설계 근거

| EXP 단계 | DataComp 대응 |
|---------|--------------|
| EXP-003 Phase 0: 저품질 클립 탐색 | DataComp 발견 1: 필터링 우선 |
| EXP-003 Phase A: 갭 클립 우선순위 | DataComp 발견 2: 롱테일 보호 |
| EXP-004: 최종 큐레이션 파이프라인 | DataComp 발견 3: 순서 결합이 최선 |
