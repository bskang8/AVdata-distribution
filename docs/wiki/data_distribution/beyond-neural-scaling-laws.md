## 핵심 아이디어

"더 많은 데이터"가 항상 답은 아니다. **"easy" 샘플(prototype에 가까운 중복 데이터)을 제거**하는 data pruning이 단순 스케일업보다 나은 스케일링을 달성할 수 있음을 이론·실험으로 증명.  
각 데이터 포인트의 prototype distance를 기하학적으로 계산하여, "hard-to-learn" 샘플만 남기고 "easy/redundant" 샘플을 제거하면 같은 데이터 수에서 성능이 향상된다.  
CIFAR, ImageNet에서 원본의 50~90%만 사용해도 동일하거나 더 좋은 성능을 달성함.

### 기하학적 프루닝 메커니즘

데이터 포인트를 임베딩 공간에서 prototype(클래스 중심)과의 거리로 분류:

```
prototype distance(x_i) = ||embedding(x_i) - prototype(class(x_i))||

"easy" (제거 대상): prototype과 매우 가까운 샘플 → 중복·과잉 정보
"hard" (유지 대상): prototype에서 멀거나 결정 경계 근처 샘플 → 고유 정보
```

**프루닝 순서**: 가장 쉬운 샘플(distance 작은 것)부터 제거 → 잔류 데이터의 정보 밀도 상승

### 스케일링 법칙과 프루닝 효과

표준 스케일링 법칙: 오류가 데이터 크기의 멱함수로 감소

```
Error ∝ N^{-α}
```

| 방법 | 지수 α | 동일 성능 도달에 필요한 데이터 |
|------|--------|-------------------------------|
| 무작위 샘플링 (기준) | α ≈ 0.35 | N |
| Easy 샘플 프루닝 30% | α ≈ 0.50 | ~0.5 N |
| Easy 샘플 프루닝 50% | α ≈ 0.70 | ~0.25 N |

→ 프루닝 후 α가 더 가파르게 증가: **데이터 효율이 기하급수적으로 개선**

### 실험 결과

| 데이터셋 | 사용 데이터 비율 | 결과 |
|---------|----------------|------|
| CIFAR-10 | 50% (프루닝) | 100% 무작위 대비 동등 성능 |
| ImageNet | 70% (프루닝) | 100% 무작위 대비 동등 성능 |
| ImageNet | 90% (프루닝) | 100% 무작위 대비 약 0.5% 성능 향상 |

## 장단점

**장점**
- 추가 데이터 수집 비용 없이 기존 데이터셋 재구성만으로 성능 향상
- 이론적 근거(기하학적 분석) 위에 실증적 검증까지 제시
- 임베딩 기반이므로 도메인에 관계없이 적용 가능 (언어/비전/오디오)
- "더 적은 데이터로 더 좋은 성능" → 라벨링 비용 절감 효과

**단점**
- 언제 프루닝을 멈출지(최적 비율) 판단 기준이 불명확
- 매우 희귀 클래스에서는 해당 클래스의 "easy" 샘플마저 중요할 수 있음 → 역효과 위험
- Prototype 계산에 사전 임베딩 모델 품질에 의존
- 클래스 불균형이 심한 경우 희귀 클래스 샘플이 과도하게 제거될 수 있음

## 프로젝트 적용 포인트

### Gap-4 연결

현재 D_train에서 맑은 날 직진 클립이 전체의 71%를 차지하는 상황이 이 논문의 핵심 문제의식과 정확히 일치한다.  
맑은 날 직진 클립 = "easy/redundant" 샘플 (모두 동일 prototype 근처에 밀집).  
이들을 제거하고 확보한 학습 예산으로 야간/우천/교차로 클립을 추가하면, 총 데이터 수를 늘리지 않고도 성능 향상 가능.

**구현 아이디어:**
```python
# Step 1: 83k 캡션 임베딩 (CLIP 또는 기존 캡션 임베더 활용)
# Step 2: 시나리오별 prototype 계산 (클러스터 중심)
# Step 3: 각 클립의 prototype distance 계산
# Step 4: distance 하위 X%를 "easy" 후보로 마킹
# Step 5: easy 클립 제거 후 gap 시나리오 클립으로 교체
```

**기대 효과**: 83k → 60k 프루닝 후, 절약된 23k 슬롯을 야간(8k) + 우천(8k) + 교차로(7k)로 채움

### EXP-003 / EXP-004 연결
- EXP-003 Phase 0: SANFlow 밀도 맵에서 density 상위 30% (과잉 영역) = "easy" 후보 식별
- EXP-004: 데이터 가치 평가 지표로 prototype distance 활용, 프루닝 비율별 Recall@5 변화 측정
- 이론 기반: "더 많은 데이터"가 아니라 "더 좋은 구성"이 정답임을 정당화
